# Experiment Artifacts Directory

**Directory:** `experiments/window_alignment/artifacts/`

## Purpose
This directory stores trained model checkpoints (`.pkl`), candidate deployment packages, and FPGA memory initialization files generated by the window alignment experiment suite.

## Subdirectories
- `window_1s_fpga_aligned/models/`: Contains fold-level pickled models and full-dataset deployment candidate models for Configuration A (1.0s window).
- `window_2s_software_baseline/models/`: Contains fold-level pickled models for Configuration B (2.0s window).
- `candidate_models/<model_id>/`: Self-contained, FPGA-ready candidate model packages.

## Candidate Model Package Contents
Each exported candidate directory contains:
1. `weights.mem`: Exactly 176 lines, 16-bit signed two's complement hex (`%04X`), compatible with `$readmemh`.
2. `bias.mem`: Exactly 1 line, 32-bit signed two's complement hex (`%08X`), compatible with `$readmemh`.
3. `model_metadata.json`: Complete record of scaling factors ($S_M$), effective unscaled weights, intercept, training timestamp, and configuration parameters.
4. `feature_order.json`: Complete 176-entry map matching channel, subband, and feature type to hardware memory address.
5. `export_validation.json`: Verification report certifying `$readmemh` compliance and bit-exact score reproduction.
6. `expected_features.hex`: Reference multi-window feature vectors.
7. `expected_scores.hex`: 40-bit signed accumulator output vectors.
8. `expected_decisions.hex`: 1-bit classifier decision outputs.

## Critical Safety Policy
- **Never Overwrite Active Hardware Files:** Active FPGA files in `rtl/weights.mem` and `rtl/bias.mem` must NOT be overwritten by experiment runs.
- **Explicit Candidate Status:** All artifacts in this directory remain candidate models until formally reviewed and accepted.
- **Separation of Evidence:** Models trained on all records for deployment are explicitly distinguished from LORO cross-validation fold models.
